# Revslot — 취업 포트폴리오 설명

## 프로젝트 개요

예약형 사업자의 당일 취소 시간을 소멸성 재고로 정의하고, 취소 감지부터 가격 계산·고객 매칭·오퍼·재평가·재예약·회수 매출 기록까지 연결한 웹 애플리케이션이다. Beauty & Wellness를 초기 범위로 정했으며, 모든 사업자·고객·수요·예약 금액은 합성 시연 데이터다. 실제 고객이나 매출 실적을 주장하지 않는다.

## 수행 과정

공식 규정과 수상작·경쟁사 자료를 먼저 검토했다. ClassPass 등에서 이미 수요 기반 가격과 자연판매 보호를 제공한다는 사실을 확인하고, 새로운 할인 알고리즘이라는 주장 대신 취소별 실행 기록과 판매자 통제에 초점을 좁혔다.

Next.js/TypeScript 화면과 FastAPI/Pydantic/LangGraph 워크플로를 구현했다. LLM은 허용된 실행 전략과 설명만 담당하고, 가격·예상매출·고객 자격·정책·예약 처리는 Python으로 분리했다. 최저가·최소마진·최대할인·승인·동일 슬롯 동일가·오래된 견적 거절·동시 예약 충돌을 서버에서 검사한다. SQLite의 조건부 갱신 SQL로 상태 버전을 비교하고 충돌 시 재확인을 요구한다.

180일, 3개 사업자, 6개 서비스의 합성 예약 12,000건을 생성했다. 시계열 순서로 학습/검증/평가를 나누고, 별도 시드의 1,000개 취소 시나리오에서 무대응·대기명단·고정할인·회수정책을 비교했다. 같은 난수·잠재 수요를 공유해 비교 변동을 줄이고, 가격 민감도 변화와 불필요한 할인도 함께 보고했다.

첫 비교가 기대에 못 미친 결과도 보존했다. 남은 시간이 0에 가까워져도 판매 확률이 남는 모델 문제를 발견해 시간당 도착 과정과 일관된 형태로 수정했다. 최종 시뮬레이션에서도 평균 할인·불필요한 할인 등의 불리한 지표를 숨기지 않았다.

## 현재 검증 범위

42개 Python 테스트, 프로덕션 빌드와 전체 흐름·승인·모바일을 다룬 브라우저 테스트 4개가 CI에서 통과했다. 실제 캡처 9개를 확인했다. 실제 Nebius/NVIDIA·Tavily 호출은 키 연결 후 검증해야 한다. 공개 배포·최종 제출 영상의 상태는 QA 보고서를 따른다. 실제 데이터 효과, 상용 보안, 실결제·문자·POS 연동은 구현 완료로 기재하지 않는다.

## 이력서용 3줄

- 당일 취소를 소멸성 재고 문제로 정의하고 Next.js·FastAPI·LangGraph로 가격·고객 매칭·재평가·재예약을 연결한 회수 워크플로 구현.
- 정수 단위 가격 계산, 마진·할인·승인 정책, 견적 버전 검증과 SQL 원자적 갱신으로 잘못된 가격 적용·중복 예약을 방지하고 42개 테스트로 검증.
- 합성 예약 12,000건과 별도 시드 1,000개 취소 시나리오로 네 가지 정책을 비교하고, 시간순 검증·짝지은 불확실성 구간·민감도·불필요 할인 한계를 함께 기록.

## 면접 STAR

**S:** 예약 시간은 시작 시각이 지나면 다시 팔 수 없고, 알림만 보내서는 가격과 대상·시간의 상호작용을 설명하기 어렵다고 보았다.

**T:** 단순 챗봇이나 할인 목록이 아니라 취소부터 결과까지 이어지고 판매자가 통제할 수 있는 검증 가능한 시제품을 만드는 것이 목표였다.

**A:** 경쟁 조사로 차별 주장을 수정하고, 모델과 금액 계산을 분리했다. 버전별 견적·승인과 원자적 상태 갱신을 구현했다. 합성 처리임을 표시하고 네 정책을 같은 시나리오로 비교했다. 첫 실패와 모델 수정 이유도 보존했다.

**R:** API 시연에서 $80 슬롯을 $64로 제안한 뒤 미판매를 확인하고 $56으로 재평가·예약해 원래 예약 금액의 70%을 기록했다. 이것은 실제 영업 실적이 아닌 합성 예약 결과다. 평가의 수익·마진·할인 간 상충과 외부 검증 한계를 설명할 수 있게 됐다.
