# 취소된 예약을 소멸성 재고로 다루기: Revslot 구현 기록

예약형 사업자의 재고는 시간이다. 오늘 저녁 8시의 마사지 예약이 오후 5시에 취소되면, 사업자에게 남은 판매 시간은 세 시간이다. 시작 시각이 지나면 그 시간을 내일 판매할 수 없다. Revslot은 취소 감지, 가격 계산, 고객 매칭, 오퍼 게시, 미판매 관찰, 재평가, 예약 확정, 결과 기록을 연결한 시제품이다.

사업자·고객·수요와 금액은 모두 합성 시연 데이터다. 실제 고객이나 매출 성과는 없다. Nebius/NVIDIA와 Tavily 연결 코드는 구현했지만 키 연결 전에는 규칙 기반 미리보기로 표시한다. 실제 추론과 공개 배포의 상태는 [QA 보고서](QA_REPORT.md)를 따른다.

## 경쟁 조사로 차별 주장을 수정했다

처음의 설명은 “AI가 취소 시간을 할인해 다시 판매한다”였다. 그러나 조사 결과 대기명단 알림, 마켓플레이스, 동적 가격은 이미 존재했다. ClassPass는 자연판매 가능성을 보호하는 수요 모델과 가격·전환율 기반 예상매출 최적화를 설명한다. Fresha 등도 예약 자동화를 제공한다.

동적 가격 자체를 새로운 발명이라고 주장하지 않았다. 범위를 Beauty & Wellness로 좁히고, 판매자가 취소 한 건의 가격·대상·시간·정책·결과를 따라갈 수 있는 실행 루프를 만들었다. 차별 주장은 [경쟁 비교](../research/COMPETITOR_MATRIX.md)의 공개 근거 범위 안에서만 한다.

## LLM과 금액 계산을 분리했다

LLM에는 게시, 대상 확대, 대기, 판매자 검토 요청이라는 제한된 행동을 허용한다. 짧은 설명과 오퍼 제목도 만들 수 있다. 가격·자격·정책·예약·매출 계산은 Python이 담당한다.

정수 센트 단위로 후보 가격을 만들고 각 후보의 `가격 × 남은 시간 안에 판매될 확률`을 비교한다. 최저가, 비용과 최소마진, 최대할인을 먼저 적용한 뒤 허용된 후보 중 예상매출이 가장 큰 것을 고른다. 동률이면 할인이 작은 후보를 선택한다. 모델 출력에 임의의 가격이 있어도 예약 금액으로 사용하지 않는다.

자연판매 확률은 회수 노출이 없는 상태를 뜻한다. 반면 가격 그래프의 0% 할인 후보도 마켓플레이스와 알림 노출을 포함한다. 두 확률을 같은 기준선으로 해석하면 안 된다. 노출 반경은 현재 실제 광고 도달률이 아니라 합성 모델의 대리 변수다.

## 에이전트 수보다 상태 전이를 명확히 했다

LangGraph의 세 노드가 분석, 계획, 실행을 맡는다. 수요 분석, 오케스트레이션, 가격 전략, 매칭, 회수 운영, 결과 분석은 별도의 책임이지만 각각 독립적인 LLM 프로세스는 아니다. 공유 상태에서 실제 도구 결과를 전달한다.

미판매 상태에서 시연 시간을 20분 진행하면 다시 분석한다. 현재 상태와 남은 시간을 입력으로 새 가격·반경·오퍼 버전을 만든다. 모델이 대기를 선택하면 새 오퍼를 자동 게시하지 않는다. 출력 형식이 깨지거나 설정된 추론이 실패하면 검토 상태로 내려간다.

화면에는 내부 사고 과정 대신 실제 행동 기록을 보여준다. 어떤 도구를 호출했고, 어떤 정책을 통과했으며, 무엇을 게시했는지 확인할 수 있다. 설명 문장과 가격 계산의 책임을 분리한 이유다.

## 승인과 예약은 같은 가격 버전을 검사해야 했다

가격이 바뀐 뒤 이전 승인이나 이전 브라우저 화면으로 예약할 수 있다면 잘못된 금액이 적용된다. 오퍼마다 버전을 두고 승인과 예약 모두 현재 버전을 확인한다. 오래된 오퍼와 중복 예약은 충돌 응답으로 거절한다.

저장소에는 상태 버전 비교를 포함한 조건부 SQL 갱신을 사용한다. 두 요청이 같은 버전을 읽어도 하나만 성공한다. 승인으로 최저가나 최소마진을 무시할 수 없고, 정책을 변경하면 게시 중인 오퍼도 다시 검사한다. SQLite는 로컬 단일 인스턴스에 사용하며 서버리스 임시 디스크는 영속 저장소라고 설명하지 않는다.

## 합성 데이터에서도 모델 문제가 드러났다

180일, 3개 사업자, 6개 서비스의 예약 이벤트 12,000건을 생성했다. 취소는 모델 학습을 위해 의도적으로 많이 포함했다. 데이터의 약 42%라는 취소 비중은 업계 통계가 아니다.

시간순으로 앞 70%를 학습, 다음 15%를 예약 구간, 마지막 15%를 평가 구간으로 나눴다. 예약 성공 여부나 재예약 소요 시간처럼 결과를 알려주는 필드를 예측 입력에 넣지 않았다. 계수는 실행 가능한 pickle 대신 JSON으로 저장한다.

초기 평가에서는 남은 시간이 0에 가까워져도 판매 확률이 남는 문제를 발견했다. 이를 시간에 따른 도착 과정과 맞는 complementary-log-log 형태와 고정 log(time) 항으로 수정했다. 실패한 개발 결과도 저장했다. 다만 생성기와 예측 모델이 유사한 구조를 공유한다. 높은 합성 점수를 실제 수요 예측 정확도라고 부를 수 없다.

## 최종 비교의 불리한 지표도 남겼다

정책을 고정한 뒤 별도 시드의 취소 시나리오 1,000개에서 네 가지 대응을 비교했다. 같은 잠재 수요와 난수를 사용해 비교 변동을 줄이고 가격 민감도를 바꾼 결과도 기록했다. 이 수치 비교에는 LLM이 참여하지 않는다.

| 합성 정책 | 취소 슬롯당 매출 | 판매율 | 평균 할인 |
|---|---:|---:|---:|
| 무대응 | $14.12 | 18.8% | 0% |
| 대기명단만 알림 | $15.47 | 20.5% | 0% |
| 고정 20% 할인 | $48.70 | 81.4% | 20% |
| Revslot 회수 정책 | $53.17 | 92.5% | 22.95% |

회수 정책은 이 모델에서 총 예약 금액을 더 기록했지만 평균 할인은 컸고, 판매된 슬롯의 평균 회수 시간도 더 길었다. 정가 판매가 일어났을 합성 반사실 슬롯이 할인에 노출된 비율은 두 할인 정책 모두 100%였다. 따라서 불필요한 할인을 줄였다는 결론은 내릴 수 없다.

이 결과는 재현 가능한 실험과 정책의 상충을 보여준다. 실제 효과를 입증하려면 동의된 대조 실험, 채널별 도달률, 실제 전환·이탈, 가격 탄력성, 수수료와 서비스 비용이 필요하다. 할인으로 생긴 예약과 원래 정가로 팔렸을 예약도 구분해야 한다.

## 화면이 아니라 전체 흐름을 검증했다

42개 Python 테스트는 금액 제약, 자격·수신 거부, 승인, 만료, 오래된 견적, 동시 갱신, 감사 기록, 공급자 실패를 검사한다. Playwright는 실제 Next.js 프로덕션 빌드와 FastAPI를 실행해 취소→재가격→예약→매출 반영, 승인, 모바일 탐색을 검증했다.

첫 브라우저 실행은 개발 서버 리소스의 출처 문제로 초기 화면에서 멈췄다. 실패 화면과 로그를 근거로 초기화와 개발 출처 설정을 수정하고 배포용 빌드로 검증을 전환했다. 실제 캡처에서 작은 글자와 화면 가림도 확인해 수정했다. 통과 여부와 CI 링크는 QA 보고서에 남긴다.
